1. Summary

  • Shorts Upload is a personal tool. Its developer and only user is the Twitch streamer Musaabi. It uploads clips from Musaabi’s own streams to Musaabi’s own YouTube channels.
  • Shorts Upload uses YouTube API Services. Everything it stores stays on Musaabi’s own PC.
  • Data is sent only to Google and YouTube, as far as the uploads need it. Nothing is sold or shared with anyone else. There is no advertising, no analytics, no tracking and no AI training.
  • Access can be revoked at any time, with the tool’s abmelden command or on Google’s security settings page; the stored data is then deleted as described below.

2. Who is responsible

Shorts Upload is developed and operated by Musaabi, who is also its only user. Contact for all privacy questions: musaabii47@gmail.com

Shorts Upload may only be used once this Privacy Policy has been accepted. Before a Google account is connected, the tool shows the link to this policy with its date and asks for explicit agreement; without a “yes”, no account is connected and nothing is stored. For each account, the tool records when the policy was accepted and which version, and it uploads only through accounts that have accepted the current version (section 15).

3. YouTube API Services and the Google Privacy Policy

Shorts Upload uses YouTube API Services. It uses the YouTube Data API v3 to upload videos (videos.insert) and to read the name of the connected channel (channels.list with mine=true).

Google processes the data that Shorts Upload sends to Google and YouTube under the Google Privacy Policy: http://www.google.com/policies/privacy

Using Shorts Upload also means agreeing to the YouTube Terms of Service: https://www.youtube.com/t/terms

4. Data Shorts Upload accesses, and why

For each connected Google account, Shorts Upload requests exactly the following permissions (OAuth scopes), and no others:

Upload videos https://www.googleapis.com/auth/youtube.upload

Used to upload a clip to the connected YouTube channel.

Sent to YouTube: the video file; its title, description and tags (see “Local files” below); the category and language set in the tool’s settings (currently Gaming and German); the visibility chosen in the settings (public, unlisted or private); the declaration whether the video is made for kids, as set in the settings and confirmed by Musaabi when the account was connected; and whether subscribers are notified, also as set in the settings.

Kept from YouTube’s reply: the ID of the new video and its visibility status.

Read the channel name https://www.googleapis.com/auth/youtube.readonly

Used when an account is connected and before uploads to it, to ask YouTube for the basic details of the account’s own channel (channels.list with mine=true). Shorts Upload uses only the channel’s name: it is shown and written to the log, to confirm and record which channel receives each upload.

Shorts Upload does not read videos, comments, subscribers, playlists, statistics or analytics.

Confirm the Google account https://www.googleapis.com/auth/userinfo.email openid

Used when an account is connected: Shorts Upload reads the email address of the Google account that signed in and compares it with the address Musaabi entered in the tool’s settings for that channel. If they do not match, the tool immediately revokes the access it has just received and saves nothing. It does the same if the account has no YouTube channel or if the automatic uploads are not allowed.

openid is part of Google’s standard sign-in. Shorts Upload does not use or store the account ID it provides.

Sign-in tokens. After sign-in, Google issues an access token and a refresh token. They let Shorts Upload act for the account within the permissions above, without a new sign-in each time.

No passwords. Sign-in takes place on Google’s own pages in the computer’s web browser. Shorts Upload never sees, asks for or stores a Google password.

Local files. Shorts Upload also reads the clip files in Musaabi’s clip folder and, in each folder, the text file upload-texte.txt that Musaabi prepares there. For each clip that is to be uploaded, it contains the title, description, hashtags and tags and a score. Shorts Upload uploads only clips that have a title and a description in this file, those with the highest score first. These texts come from Musaabi, not from Google.

5. What is stored, and where

Everything is stored only on Musaabi’s own Windows PC, in the tool’s folder. There is no server, no cloud storage and no database anywhere else.

  • Sign-in tokens (one encrypted file per connected account, see section 13): the access token and refresh token issued by Google, the granted permissions, the token’s expiry time and the technical details needed to renew it.
  • Upload history: for each upload, the clip’s file name and folder, the account’s local label (a short name chosen by Musaabi), the title, the YouTube video ID, the visibility status reported by YouTube, and the date and time. For clips that YouTube rejected: the file name, YouTube’s error code and the date.
  • Log file: a record of each run with date and time, containing account labels, the name of the channel each upload goes to, clip file names, titles and scores, links to uploaded videos (which contain the video ID), the visibility and any error messages or notes (for example about clips whose texts do not fit YouTube’s limits). When an account is connected, the log also records that account’s email address, its channel name and the upload settings that were agreed to.
  • Consent records: for each account, when Musaabi accepted this Privacy Policy and allowed the automatic uploads, which version of the policy was accepted, and the upload settings that were agreed to (clip folder, daily limit, visibility, the “made for kids” declaration and whether subscribers are notified). These are not data obtained from Google.
  • Settings: a configuration file that Musaabi writes by hand, with a label and the expected email address for each account, the clip folder and the upload settings. These are not data obtained from Google.

6. How the data is used

The data is used only to:

  • upload each clip to the intended channel;
  • confirm that the right Google account and channel are connected;
  • make sure that every clip is uploaded only once and that the daily limit is kept;
  • show Musaabi what was uploaded where, and find and fix errors.

It is not used for anything else: no profiling, advertising, analytics or selling, and no training of AI or machine-learning models. Nobody other than Musaabi uses the data.

7. Sharing: only with Google and YouTube

Data is sent only to Google, and only as far as the functions above need it: to Google’s sign-in and account services (to sign in, to read the account’s email address, and to renew or revoke tokens) and to the YouTube Data API (to upload videos and read the channel name). When an account is connected, Shorts Upload also passes the expected email address to Google’s sign-in page so that the right account is preselected. All connections to Google are encrypted (HTTPS).

No other internal or external party receives any data. Shorts Upload does not sell, rent or share data, does not show advertising and does not allow third parties to serve content or ads.

8. Storage on the device and cookies

Shorts Upload stores the files described in section 5 on Musaabi’s PC and reads the clip files and text files mentioned in section 4. Besides these, it only creates a temporary lock file that prevents two runs at the same time. It does not access or collect any other information on the device, and it does not use cookies or similar technologies. During sign-in, Google’s pages in the web browser may use Google’s own cookies; these are covered by the Google Privacy Policy.

9. How long data is kept

  • Sign-in tokens: as long as the account is connected. They are deleted when the account is disconnected (section 10) or when Shorts Upload notices that its access has ended (section 11).
  • YouTube video IDs, titles and visibility statuses in the upload history: deleted automatically once they are 30 days old.
  • Log entries, including email addresses and channel names: deleted automatically once they are 30 days old.
  • The rest of the upload history (clip file name, account label, date and time of the upload, and the error code of rejected clips): kept while Shorts Upload is in use, so that no clip is ever uploaded twice. It contains no video IDs, no titles and no data from the Google account.
  • Consent records: until the account is disconnected with abmelden or agreement is refused when the account is connected again.
  • Settings: until Musaabi changes them.

The automatic deletion runs at the start of every scheduled run of the tool (three times a day, even when there is nothing to upload) and whenever the status command is used. When Shorts Upload is no longer used, Musaabi disconnects every account with abmelden (section 10) and deletes the log file and the upload history.

10. Disconnecting an account and deleting data

The command upload_shorts.py abmelden <account> disconnects an account. It:

  1. revokes the account’s token at Google right away, which ends Shorts Upload’s access to that Google account and its YouTube channel;
  2. deletes the account’s token file and its consent record on the PC;
  3. deletes the YouTube and Google data stored for that account: the video IDs, titles and visibility statuses in the upload history, and all of the account’s entries in the log, including its email address, channel name and video links.

This happens immediately when the command runs, and in any case within 7 days. Only the minimal record described in section 9 remains, so that the clips are not uploaded again. If Google cannot be reached (for example, without an internet connection), the local data is deleted anyway; the access should then also be removed on Google’s security settings page (section 11).

Deletion can also be requested by email to musaabii47@gmail.com. Such requests are carried out within 7 days.

Important: Deleting data in Shorts Upload does not affect anything stored on YouTube. Uploaded videos stay on YouTube. To delete them, use YouTube Studio or the YouTube app.

11. Revoking access through Google

In addition to the tool’s own way of deleting data (section 10), access can be revoked at any time on Google’s security settings page: https://security.google.com/settings/security/permissions. There, select Shorts Upload and remove its access.

If access is revoked there, or if a token can no longer be renewed for any other reason, Shorts Upload notices this the next time it renews that account’s token before an upload. It then immediately deletes the account’s token file and its stored YouTube and Google data, in the same way as in section 10. Independently of this, the automatic deletion described in section 9 removes stored YouTube data and log entries once they are 30 days old, so none of this data is kept longer than 30 days after a revocation.

12. Limited Use

Shorts Upload’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Data received from Google APIs is used only to provide the upload functions described here. It is not transferred to anyone else, not sold, not used for advertising, not used to train AI or machine-learning models, and not read by any person other than Musaabi.

13. Security

All connections to Google are encrypted (HTTPS). Sign-in tokens are stored encrypted with the Windows Data Protection API (DPAPI), so only Musaabi’s Windows user account on that PC can read them. The tool’s data stays on Musaabi’s PC and is never published. Sign-in tokens and the tool’s Google credentials are never shared and are not part of the public repository of this website, which contains only the website itself.

14. This website

This website is hosted on GitHub Pages, a service provided by GitHub. When you visit it, GitHub logs your IP address for security purposes, whether or not you are signed in to GitHub. How GitHub handles this data is described in the GitHub General Privacy Statement.

The website itself uses no cookies, analytics, tracking or advertising. It loads no fonts, scripts or images from other servers and embeds no third-party content. Musaabi does not collect any data about visitors.

15. Changes to this policy

If this policy changes, the new version will be published on this page with a new date, and Shorts Upload asks for agreement again: it uploads nothing through an account until the new version has been accepted for that account when it is connected again. If Shorts Upload starts to use data in a new way, it will do so only after the updated policy has been accepted.

16. Contact

Questions or complaints about privacy, and requests for information or deletion: musaabii47@gmail.com

4. Welche Daten Shorts Upload abruft und wozu

Für jedes verbundene Google-Konto fragt Shorts Upload genau die folgenden Berechtigungen (OAuth-Scopes) an – und keine weiteren:

Videos hochladen https://www.googleapis.com/auth/youtube.upload

Damit lädt Shorts Upload einen Clip auf den verbundenen YouTube-Kanal hoch.

An YouTube gesendet werden: die Videodatei; Titel, Beschreibung und Tags (siehe „Lokale Dateien“ unten); Kategorie und Sprache aus den Einstellungen des Programms (derzeit Gaming und Deutsch); die in den Einstellungen gewählte Sichtbarkeit (öffentlich, nicht gelistet oder privat); die in den Einstellungen festgelegte und von Musaabi beim Verbinden des Kontos bestätigte Angabe, ob das Video speziell für Kinder ist; und ob Abonnenten benachrichtigt werden, ebenfalls wie in den Einstellungen festgelegt.

Aus der Antwort von YouTube behalten werden: die ID des neuen Videos und sein Sichtbarkeitsstatus.

Kanalnamen lesen https://www.googleapis.com/auth/youtube.readonly

Damit fragt Shorts Upload beim Verbinden eines Kontos und vor Uploads darauf bei YouTube die Basisdaten des eigenen Kanals des Kontos ab (channels.list mit mine=true). Verwendet wird davon nur der Kanalname: Er wird angezeigt und ins Protokoll geschrieben, um zu bestätigen und festzuhalten, welcher Kanal jeden Upload erhält.

Shorts Upload liest keine Videos, Kommentare, Abonnenten, Playlists, Statistiken oder Analysedaten.

Google-Konto bestätigen https://www.googleapis.com/auth/userinfo.email openid

Beim Verbinden eines Kontos liest Shorts Upload die E-Mail-Adresse des angemeldeten Google-Kontos und vergleicht sie mit der Adresse, die Musaabi in den Einstellungen für diesen Kanal eingetragen hat. Stimmen sie nicht überein, widerruft das Programm sofort den gerade erhaltenen Zugriff und speichert nichts. Ebenso verfährt es, wenn das Konto keinen YouTube-Kanal hat oder die automatischen Uploads nicht erlaubt werden.

openid gehört zur Standard-Anmeldung von Google. Die damit übermittelte Konto-ID nutzt und speichert Shorts Upload nicht.

Anmelde-Tokens. Nach der Anmeldung stellt Google ein Zugriffstoken und ein Aktualisierungstoken (Access- und Refresh-Token) aus. Damit kann Shorts Upload im Rahmen der obigen Berechtigungen für das Konto handeln, ohne dass jedes Mal eine neue Anmeldung nötig ist.

Keine Passwörter. Die Anmeldung läuft auf den Seiten von Google im Webbrowser des Computers. Shorts Upload sieht, erfragt und speichert keine Google-Passwörter.

Lokale Dateien. Außerdem liest Shorts Upload die Clip-Dateien in Musaabis Clip-Ordner und in jedem Ordner die Textdatei upload-texte.txt, die Musaabi dort vorbereitet. Sie enthält für jeden Clip, der hochgeladen werden soll, Titel, Beschreibung, Hashtags und Tags sowie einen Score. Shorts Upload lädt nur Clips hoch, die in dieser Datei einen Titel und eine Beschreibung haben, und zwar die mit dem höchsten Score zuerst. Diese Texte stammen von Musaabi, nicht von Google.

5. Was gespeichert wird und wo

Alles wird ausschließlich auf Musaabis eigenem Windows-PC im Ordner des Programms gespeichert. Es gibt keinen Server, keinen Cloud-Speicher und keine Datenbank an anderer Stelle.

  • Anmelde-Tokens (eine verschlüsselte Datei je verbundenem Konto, siehe Abschnitt 13): Zugriffs- und Aktualisierungstoken von Google, die erteilten Berechtigungen, der Ablaufzeitpunkt des Tokens und die technischen Angaben, die zum Erneuern nötig sind.
  • Upload-Verlauf: je Upload Dateiname und Ordner des Clips, die lokale Bezeichnung des Kontos (ein kurzer, von Musaabi gewählter Name), der Titel, die YouTube-Video-ID, der von YouTube gemeldete Sichtbarkeitsstatus sowie Datum und Uhrzeit. Für Clips, die YouTube abgelehnt hat: Dateiname, Fehlercode von YouTube und Datum.
  • Protokolldatei: ein Protokoll jedes Laufs mit Datum und Uhrzeit, mit Kontobezeichnungen, dem Namen des Kanals, auf den ein Upload geht, Clip-Dateinamen, Titeln und Scores, Links zu hochgeladenen Videos (sie enthalten die Video-ID), der Sichtbarkeit und etwaigen Fehlermeldungen oder Hinweisen (zum Beispiel zu Clips, deren Texte nicht in die Grenzen von YouTube passen). Beim Verbinden eines Kontos hält das Protokoll außerdem dessen E-Mail-Adresse, Kanalnamen und die Upload-Einstellungen fest, denen zugestimmt wurde.
  • Einwilligungen: je Konto, wann Musaabi dieser Datenschutzerklärung zugestimmt und die automatischen Uploads erlaubt hat, welcher Fassung der Datenschutzerklärung zugestimmt wurde und die Upload-Einstellungen, denen zugestimmt wurde (Clip-Ordner, Tageslimit, Sichtbarkeit, die Angabe „speziell für Kinder“ und die Benachrichtigung der Abonnenten). Diese Daten stammen nicht von Google.
  • Einstellungen: eine Konfigurationsdatei, die Musaabi von Hand schreibt – je Konto eine Bezeichnung und die erwartete E-Mail-Adresse, außerdem der Clip-Ordner und die Upload-Einstellungen. Diese Daten stammen nicht von Google.

6. Wofür die Daten verwendet werden

Die Daten werden nur verwendet, um

  • jeden Clip auf den vorgesehenen Kanal hochzuladen,
  • zu bestätigen, dass das richtige Google-Konto und der richtige Kanal verbunden sind,
  • sicherzustellen, dass jeder Clip nur einmal hochgeladen und das Tageslimit eingehalten wird,
  • Musaabi anzuzeigen, was wohin hochgeladen wurde, und Fehler zu finden und zu beheben.

Für nichts anderes: keine Profilbildung, keine Werbung, keine Analyse, kein Verkauf und kein Training von KI- oder Machine-Learning-Modellen. Niemand außer Musaabi nutzt die Daten.

7. Weitergabe: nur an Google und YouTube

Daten gehen nur an Google und nur, soweit es die genannten Funktionen erfordern: an die Anmelde- und Kontodienste von Google (zum Anmelden, zum Lesen der E-Mail-Adresse des Kontos sowie zum Erneuern und Widerrufen von Tokens) und an die YouTube Data API (zum Hochladen von Videos und zum Lesen des Kanalnamens). Beim Verbinden eines Kontos übergibt Shorts Upload außerdem die erwartete E-Mail-Adresse an die Anmeldeseite von Google, damit das richtige Konto vorausgewählt ist. Alle Verbindungen zu Google sind verschlüsselt (HTTPS).

Keine andere interne oder externe Stelle erhält Daten. Shorts Upload verkauft, vermietet und teilt keine Daten, zeigt keine Werbung und lässt keine Dritten Inhalte oder Werbung einblenden.

8. Speicherung auf dem Gerät und Cookies

Shorts Upload speichert die in Abschnitt 5 genannten Dateien auf Musaabis PC und liest die in Abschnitt 4 genannten Clip- und Textdateien. Daneben legt es nur eine kurzzeitige Sperrdatei an, die verhindert, dass zwei Läufe gleichzeitig starten. Auf andere Informationen auf dem Gerät greift es nicht zu, es erhebt keine weiteren Daten und verwendet weder Cookies noch ähnliche Techniken. Während der Anmeldung können die Seiten von Google im Webbrowser eigene Cookies von Google verwenden; dafür gilt die Datenschutzerklärung von Google.

9. Wie lange Daten gespeichert werden

  • Anmelde-Tokens: solange das Konto verbunden ist. Sie werden gelöscht, wenn das Konto getrennt wird (Abschnitt 10) oder sobald Shorts Upload bemerkt, dass sein Zugriff beendet ist (Abschnitt 11).
  • YouTube-Video-IDs, Titel und Sichtbarkeitsstatus im Upload-Verlauf: werden automatisch gelöscht, sobald sie 30 Tage alt sind.
  • Protokolleinträge, auch solche mit E-Mail-Adressen und Kanalnamen: werden automatisch gelöscht, sobald sie 30 Tage alt sind.
  • Der übrige Upload-Verlauf (Clip-Dateiname, Kontobezeichnung, Datum und Uhrzeit des Uploads sowie der Fehlercode abgelehnter Clips): bleibt erhalten, solange Shorts Upload genutzt wird, damit kein Clip jemals doppelt hochgeladen wird. Er enthält keine Video-IDs, keine Titel und keine Daten aus dem Google-Konto.
  • Einwilligungen: bis das Konto mit abmelden getrennt oder die Zustimmung beim erneuten Verbinden verweigert wird.
  • Einstellungen: bis Musaabi sie ändert.

Das automatische Löschen läuft zu Beginn jedes geplanten Laufs des Programms (dreimal täglich, auch wenn nichts hochzuladen ist) und bei jedem Aufruf des Befehls status. Wird Shorts Upload nicht mehr genutzt, trennt Musaabi jedes Konto mit abmelden (Abschnitt 10) und löscht die Protokolldatei und den Upload-Verlauf.

10. Konto trennen und Daten löschen

Der Befehl upload_shorts.py abmelden <konto> trennt ein Konto. Er

  1. widerruft das Token des Kontos sofort bei Google – damit endet der Zugriff von Shorts Upload auf dieses Google-Konto und seinen YouTube-Kanal,
  2. löscht die Token-Datei und die Einwilligung des Kontos auf dem PC und
  3. löscht die für dieses Konto gespeicherten YouTube- und Google-Daten: die Video-IDs, Titel und Sichtbarkeitsstatus im Upload-Verlauf sowie alle Protokolleinträge des Kontos, einschließlich E-Mail-Adresse, Kanalname und Video-Links.

Das geschieht sofort beim Ausführen des Befehls, in jedem Fall innerhalb von 7 Tagen. Übrig bleibt nur der in Abschnitt 9 beschriebene Mindestdatensatz, damit die Clips nicht erneut hochgeladen werden. Ist Google nicht erreichbar (zum Beispiel ohne Internetverbindung), werden die lokalen Daten trotzdem gelöscht; der Zugriff sollte dann zusätzlich auf der Google-Seite für Sicherheitseinstellungen entfernt werden (Abschnitt 11).

Eine Löschung kann auch per E-Mail an musaabii47@gmail.com verlangt werden. Solche Anfragen werden innerhalb von 7 Tagen erledigt.

Wichtig: Das Löschen von Daten in Shorts Upload wirkt sich nicht auf Daten bei YouTube aus. Hochgeladene Videos bleiben auf YouTube. Löschen lassen sie sich über YouTube Studio oder die YouTube-App.

11. Zugriff über Google widerrufen

Zusätzlich zum eigenen Löschverfahren des Programms (Abschnitt 10) lässt sich der Zugriff jederzeit auf der Google-Seite für Sicherheitseinstellungen widerrufen: https://security.google.com/settings/security/permissions. Dort Shorts Upload auswählen und den Zugriff entfernen.

Wird der Zugriff dort widerrufen oder lässt sich ein Token aus einem anderen Grund nicht mehr erneuern, bemerkt Shorts Upload das, sobald es das Token dieses Kontos vor einem Upload das nächste Mal erneuert. Es löscht dann sofort die Token-Datei und die gespeicherten YouTube- und Google-Daten des Kontos, genauso wie in Abschnitt 10. Unabhängig davon entfernt das automatische Löschen aus Abschnitt 9 gespeicherte YouTube-Daten und Protokolleinträge, sobald sie 30 Tage alt sind, sodass nichts davon länger als 30 Tage nach einem Widerruf gespeichert bleibt.

12. Eingeschränkte Nutzung (Limited Use)

Die Nutzung und Weitergabe von Informationen, die Shorts Upload über Google-APIs erhält, entspricht der Google API Services User Data Policy einschließlich der Anforderungen zur eingeschränkten Nutzung (Limited Use requirements). Daten aus Google-APIs werden nur für die hier beschriebenen Upload-Funktionen verwendet. Sie werden an niemanden weitergegeben, nicht verkauft, nicht für Werbung genutzt, nicht zum Training von KI- oder Machine-Learning-Modellen verwendet und von keiner Person außer Musaabi gelesen.
